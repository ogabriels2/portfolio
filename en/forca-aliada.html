My role

I lead product direction, priorities, integrations and technical decisions. I work on infrastructure, implementation review and testing with collaborators, using Claude Code and Codex to support development. The community began in 2021; software work began in November 2025.

01 / Origin and direction

A server revealed problems worth building a product for.

Running a server involves more than starting it: versions, access, backups, connectivity and communication. Força Aliada grew from this context into tools for the people who administer and participate in these environments.

For administrators

Manager brings together tasks previously scattered across folders, commands and settings. The app operates on the PC; the web console adds an organization, team and remote-action view.

For participants

Community organizes profiles, posts and conversations. A server can appear in the feed with its own context, connecting technical management to the community’s presence.

02 / The products

Different purposes, a connected experience.

The app, console and social platform have distinct tasks. Accounts, APIs and shared services connect them without requiring people to understand the architecture to use them.

Força Aliada Manager

Create. Operate.
Maintain.

A Windows app to create, import and manage Minecraft servers. It brings overview, terminal, players, files, backups, scheduling and settings together.

  • A creation wizard for different editions and configurations.
  • Terminal and logs for monitoring and diagnosis.
  • Player access, components and update management.
  • Backups, scheduling and connections across PCs.

The web console extends this operation to organizations: linked computers, servers, team roles and activity. A remote action follows authorization rules and completes only after the app confirms the result.

In the final development phase. The app and console continue to be refined and validated.

03 / Product and engineering decisions

Decisions reveal the complexity.

The work does not end with the first functioning screen. I investigate problems, guide implementation and check what happens when a connection fails, an action is repeated or a person continues in another interface.

  1. The window should not be the server.

    Operation is decoupled from the interface. The agent maintains state, scheduling and communication; the app and console present information and actions. Closing the window is not treated as the end of the operation.

  2. A sent request is not a completed action.

    A remote action has a target, authorization, expiration and protection against repetition. The result returns as confirmation. The interface distinguishes request, execution and failure rather than declaring success too early.

  3. Saved settings do not guarantee access.

    Allowlist, identity and connectivity flows need to validate results in the environment. UX keeps errors recoverable and distinguishes a reserved address, an active connection and an applied permission.

04 / How the parts connect

A platform with defined responsibilities.

The backend coordinates account, community and operation. The app handles tasks on the PC. Web interfaces provide product visibility and actions in the context of each account and organization.

Operations stay on the PC.

The app and agent handle server files, processes and tasks. The web console requests actions; completion depends on execution confirmation.

The server gains social context.

Profiles, posts, replies and conversations extend the experience. A server card connects that content to the Manager’s operational data.

APIs and data
Node.js, Express and PostgreSQL connect the ecosystem’s responsibilities.
Backend, data and integrations

Node.js and Express organize API modules; PostgreSQL persists data and relationships. Integrations include Microsoft/Xbox identity, media, communication and billing. Accounts, products and support share access rules, with separate module responsibilities.

App, agent and remote actions

Manager is built with Electron. The local agent connects PC operation to the web console. Organizations and roles limit access in the control plane; signed commands have replay protection, expiration and execution confirmation. Interfaces follow states and results rather than assuming success.

Community and content recommendation

The feed combines retrieval, affinity, diversity and ranking rules. This recommendation layer is distinct from generative AI. Profiles, social relationships, chat and server content share account context; new features are enabled and refined progressively.

Support with sources and human continuity

The support implementation consults official documentation, returns sources and supports human handoff. AI integration has usage limits and fallback; credentials are removed before prompts. Actions that change system state require confirmation instead of making silent changes.

Interface, infrastructure and validation

Cloudflare participates in web delivery, DNS and project services. Claude Code mainly supports backend and security; Codex supports interfaces and UX. My work connects planning, review, testing and integration adjustments. I evaluate real flows and failure states as well as the final appearance.
