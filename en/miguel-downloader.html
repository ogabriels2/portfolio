Miguel Downloader

A native app that turns a link into a clear task. It shows what the source actually offers, keeps each download under control, and marks a file complete only after checking it.

C# · .NET 8WPF · MVVMSQLiteWindows
See the product flow Microsoft Store

01 / The proposition

A download should not be a black box.

Quality, compatibility, queues and file integrity all change the result. Miguel Downloader makes these choices visible without expecting people to know the details of every format.

02 / Product journey

From analysis to a ready file, one step at a time.

Select a step to see the decision behind the interface. This walkthrough explains the code; it does not run a download.

SELECTED STEP

The link is understood first

MediaUrlParser identifies the service and link type. For each item, yt-dlp checks the available metadata before a person chooses an option.

Available data varies by content and source. The app does not invent resolution, HDR, subtitles or file size to fill a screen.

03 / Format decisions

The best option depends on what matters to you.

These priorities are not labels over the same selection. Each preset changes the order used to evaluate formats provided by the source.

Explore the priorities

What comes first?

Looks for the highest available resolution and preserves HDR when that option exists.

Quality puts resolution first; Compatibility starts with a playable codec; Smaller size targets an acceptable minimum height and efficient encoding. If a format is not available from the source, no preset can add it.

04 / Engineering

Native interface, testable rules and local data.

The repository separates presentation, download engine, domain rules and persistence. Each part has a responsibility and explicit contracts with the others.

Queue at scale

Batch persistence and virtualized lists avoid thousands of transactions or controls when restoring large collections.

5,000items in the test
2.9 sto save
0.4 sto restore

Times documented for the persistence layer; they are not a promise about download speed. The repository also documents unit, integration, stress and tool-installation tests.

Open technical details

Application and data

C# with self-contained .NET 8; WPF with MVVM. Core keeps rules independent of the UI and I/O. Data uses SQLite for history and queue, with settings in JSON.

Media pipeline

yt-dlp analyzes and transfers selected streams. FFmpeg combines or remuxes when needed. Deno ships as the extractor's JavaScript runtime. Bundled binaries are checked with SHA-256 during the build.

Reliability

One process per item isolates progress and recovery. The queue stores state, not expiring format URLs. When restoring a task, the app queries the source again before downloading.

05 / My contribution

An independent product, with clear authorship.

I led the product concept, requirements and technical decisions, alongside code review and behavior validation. Implementation was supported by AI.

My work was to turn the idea into a verifiable product. I reviewed flows against real downloads, failure cases and source limitations, and kept the technical documentation aligned with the application's behavior.
